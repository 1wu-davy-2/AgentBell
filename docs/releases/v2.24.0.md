## AgentBell 2.24.0

本次更新新增「会话历史流」与三种「更新上下文」接入模式：同一次 AI 对话里的多轮通知不再散落在列表里，而是按时间汇成一条连续记录；接入提醒时可按需要选择最全、开始+结束或仅结束，让 Agent 只上报真正有价值的内容，节省 Token。

### 新增

- 三种更新模式：通知中心顶栏新增模式下拉，可选「最全 / 开始+结束 / 仅结束」。
  - **最全**：静默开始，30% / 60% / 90% 关键节点更新同一张卡片，等待输入即时提醒，结束再发一条结论。
  - **开始+结束**：每轮只有静默开始与结束两条，不写中途进度。
  - **仅结束**：每轮只在结束时发一条结论，最省 Token，适合不需要过程可视化、批量调用的场景。
- 模式随接入指令生成：复制出的接入说明按当前模式裁剪字段与示例；仅结束模式不再出现 `status=running`、`phase`、`progress`、`run_id`、`dedupe_key` 与静默上报，最全模式补充 30% / 60% / 90% 更新指引与 `needs_input` / `wait_reason` 字段。
- 模式登记接口：新增 `POST /integration/report`，Agent 接入时可上报 `{agent, mode, source}`；按 Agent 记录在本机 SQLite 的 `integration_profiles` 表，重复上报同模式返回 `changed: false`。MCP `get_status` 返回 `integration_profiles`，「运行环境」页展示已登记 Agent、模式与时间。该接口与 `/notify`、`/mcp` 一样要求 Token。
- 模式持久化：配置新增 `integration_mode`，默认 `start_finish`，切换后立即写入配置文件；重启后保持上次选择。
- 会话历史流：带 `session_id` 的通知卡片右侧新增紫色「会话历史流」按钮；Agent 会话详情顶部的「本次运行」区块改为「历史流」，显示轮次数与最近运行摘要。弹窗按时间顺序排列该会话的全部通知，每轮显示时间、状态、耗时与摘要，并可展开该轮的运行事件；头部汇总 Agent、项目、会话 ID、轮次数、成功率、时间跨度与自动关联轮数。
- 自动关联：通知未显式提供 `session_id` 时，仅在「同一 Agent + 同一项目目录 + 会话在最近 30 分钟内仍有更新 + 唯一匹配」四个条件同时满足时才自动关联，并在卡片与历史流中标记「自动关联」。显式 `session_id` 始终优先；存在多个候选、目录不相关或会话过旧时不做猜测。该规则只作用于新通知，不回填历史记录。
- 事件归属：历史流按 `run_events.notification_id` 把事件归到具体轮次，不再按共享的 `run_id` 重复展示。即使同一会话的多轮通知都回落到 `session:<id>` 运行编号，每轮也只会看到自己的事件。
- 接入指令：复制给 Agent 的接入说明补充 `session_id` 建议与自动关联边界，两步时间线协议在开始与结束通知中都携带同一个 `session_id`；同时明确这些约定只用于当前对话，不写入项目文件、`CLAUDE.md`、Agent 设置或 Hook 配置。
- 存储：`notifications(session_id, received_at)` 增加索引，会话历史按时间读取；单会话事件流按 `occurred_at` 升序读取，默认上限 2000 条。

### 更新模式示意

| 模式 | 每轮请求 | 适用场景 |
| --- | --- | --- |
| `full` 最全 | 静默开始 + 30% / 60% / 90% 进度 + 等待输入 + 结束 | 长任务，需要随时看到进展 |
| `start_finish` 开始+结束 | 静默开始 + 结束 | 常规开发，兼顾时间线与安静 |
| `finish_only` 仅结束 | 结束一条 | 短任务、批量调用，最省 Token |

### API 示例

```json
{
  "title": "完成会话历史流",
  "status": "succeeded",
  "session_id": "a9cfb527-15c4-4fe8-952c-2f13fb2a984f",
  "run_id": "round-20261112-01",
  "summary": "已按会话汇总多轮通知",
  "phase": "finished"
}
```

模式登记：

```json
{"agent": "Claude Code", "mode": "finish_only", "source": "hook"}
```

```bash
curl -X POST http://127.0.0.1:8765/integration/report \
  -H "Content-Type: application/json" \
  -H "X-Token: your-token" \
  -d '{"agent":"Claude Code","mode":"start_finish"}'
```

未提供 `session_id` 时也可依赖自动关联，但只会在唯一匹配时生效；需要稳定归属时建议每轮显式携带同一个 `session_id`，并为每轮提供独立 `run_id`。

### 说明

- 会话历史流只读取本机 SQLite 中的通知与运行事件，以及已扫描到的会话元数据，不解析会话正文，也不写入任何外部服务。
- 自动关联只使用 Agent 名称、`origin.working_dir`、扫描到的会话项目路径与更新时间，不读取会话内容。
- 模式登记只保存 Agent、模式、来源和时间，不包含提示词、会话正文或密钥；无法识别的模式会被拒绝并返回 422。
- 接入指令只用于对话内约定，不会自动写入 `CLAUDE.md`、项目文件、Agent 设置或 Hook 配置；需要 Hook 时仍需在「运行环境」页手动预览并安装。
- 历史记录不会被批量补写 `session_id`；旧通知只有在原本就带 `session_id` 时才会出现在历史流里。
- 通知动作仍只读，不提供批准权限、自动继续或命令执行。

### 平台与下载

- Windows x64：`AgentBell.exe`；Windows ARM64：`AgentBell-arm64.exe`。
- macOS Intel：`AgentBell-macos-x64.dmg` / `.zip`；Apple Silicon：`AgentBell-macos-arm64.dmg` / `.zip`。
- Linux x64 / arm64：`AgentBell-linux-<arch>.tar.gz`、`.AppImage`、`.deb`、`.rpm`。
- 全部资产由 `SHA256SUMS.txt` 校验；Windows、macOS 与 Linux 便携版都支持包内自动更新。

HTTP 服务仍只监听 `127.0.0.1`，会话记录只读，通知动作不执行外部命令，也不提供批准权限或自动继续。
